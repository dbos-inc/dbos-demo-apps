Application offline — reconnecting…

Build reliable software effortlessly

DBOS adds durable execution to your applications, checkpointing their workflows and steps to Postgres. If your apps ever crash, DBOS recovers them from their last completed steps.

Try it: launch a workflow, then crash this app. When you restart, the workflow always resumes from exactly where it left off.

src/main.ts 
const workflow = DBOS.registerWorkflow(async () => {await DBOS.runStep(stepOne);await DBOS.runStep(stepTwo);await DBOS.runStep(stepThree);}); async function stepOne() {await sleep(5000);console.log("Completed step 1!");} async function stepTwo() {await sleep(5000);console.log("Completed step 2!");} async function stepThree() {await sleep(5000);console.log("Completed step 3!");}

DBOS durable workflows can be started on a cron-style schedule. The schedule can be adjusted while the app is running. It may take up to a minute for changes to propagate.

src/main.ts 
const scheduledWorkflow = DBOS.registerWorkflow(async (scheduledTime, context) => {DBOS.logger.info("Scheduled workflow starting.");await DBOS.sleep(1000);DBOS.logger.info("Scheduled workflow ending.");}); await DBOS.applySchedules([{scheduleName: "scheduled-workflow",workflowFn: scheduledWorkflow,schedule: "*/5 * * * * *",}]);

DBOS queues let you run workflow fan-outs and control concurrency. The workerConcurrency parameter controls how many workflows one process may run simultaneously. You can adjust it without restarting the app. Press "Enqueue 5 Workflows" repeatedly to put workflows on the queue.

src/main.ts 
const queueWorkflow = DBOS.registerWorkflow(async () => {await DBOS.sleep(5000);}); await DBOS.registerQueue("demo-queue",{ workerConcurrency: 3 }); await DBOS.startWorkflow(queueWorkflow,{ queueName: "demo-queue" })();

DBOS queues offer many additional controls for rate limiting, deduplication, partitioning, delayed execution, prioritization and more. See the "Pattern" pulldown for other examples.

A rate-limited queue caps how many workflows start in each time period, for example to stay under an external API's rate limit. This queue starts at most limitPerPeriod workflows every periodSec seconds, however many are waiting.

src/main.ts 
await DBOS.registerQueue("rate-limited-queue", {rateLimit: { limitPerPeriod: 2, periodSec: 10 },}); await DBOS.startWorkflow(queueWorkflow,{ queueName: "rate-limited-queue" })();

This queue allocates capacity fairly across tenants. workerConcurrency caps how many workflows may run per process, while partitionConcurrency sets a limit per tenant. For example, press "enqueue a random mix" and then add a workflow for ed. It will start in a few seconds even though the queue is full.

src/main.ts 
await DBOS.registerQueue("fair-queue", {partitionConcurrency: 1,workerConcurrency: 4,}); await DBOS.startWorkflow(queueWorkflow, {queueName: "fair-queue",enqueueOptions: { queuePartitionKey: tenantId },})();

DBOS can delay an enqueued workflow, so it waits before running. While a workflow is DELAYED, you can change its delay to run it sooner or later. The delay is stored in Postgres, so a delayed workflow still runs if your app restarts before it's due.

src/main.ts 
await DBOS.registerQueue("delayed-queue"); await DBOS.startWorkflow(queueWorkflow, {queueName: "delayed-queue",enqueueOptions: { delaySeconds },})(); // Run it sooner or later while it's still DELAYEDawait DBOS.setWorkflowDelay(workflowID, { delaySeconds });

DBOS workflows can receive messages while running, enabling inter-workflow communication and human-in-the-loop patterns. DBOS.recv() durably waits for a message, surviving crashes and restarts. Here we use DBOS.send() to deliver a decision from an endpoint.

src/main.ts 
const communicationWorkflow = DBOS.registerWorkflow(async () => {await DBOS.runStep(commStepOne);await DBOS.setEvent("comm_status", "waiting");const decision = await DBOS.recv("approval",    { timeoutSeconds: 15 });if (decision === "approve") {await DBOS.runStep(commStepTwo);} else if (decision === "deny") {DBOS.logger.info("Denied.");} else {  // timeoutthrow new Error("Timed out waiting for approval");}});
